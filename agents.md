# Experiments

## Назначение

Статический сайт-каталог независимых веб-экспериментов. Главная страница показывает список экспериментов; каждый эксперимент — отдельная HTML-страница.

## Структура

- `index.html` — каталог страниц с поиском и группами.
- `pages/` — отдельные страницы экспериментов.
  - `test.html` — минимальная тестовая страница.
  - `kinetic-form.html` — «Волновая хризантема», генеративная Canvas-анимация из группы `p5.js`.
  - `pulsing-orbits.html` — «Тройной резонанс», генеративная Canvas-анимация из группы `p5.js`.
  - `flowing-globe.html` — «Текучая сфера», генеративная Canvas-анимация из группы `p5.js`.
  - `tesseract.html` — «Тессеракт», анимированная проекция четырёхмерного куба из группы `p5.js`.
  - `penteract.html` — «Пентеракт», анимированная проекция пятимерного куба из группы `p5.js`.
  - `tidal-dome.html` — «Приливный купол», генеративная Canvas-анимация из группы `p5.js`.

## Интерфейс

- Тема всегда тёмная: задавайте `color-scheme: dark` и тёмный `theme-color`.
- На мобильных устройствах показывается только список; нажатие открывает отдельную страницу эксперимента.
- На десктопе список остаётся слева, а выбранная страница открывается справа.
- Список должен содержать только названия страниц, строку поиска и группы. Группы сворачиваются и разворачиваются; по умолчанию они раскрыты.
- На главной странице не используйте общий тулбар. Он нужен только внутри отдельных страниц экспериментов.
- Не добавляйте элементы, характерные для мессенджера: аватары, даты, превью сообщений, статусы или лишние заголовки.
- Сохраняйте простую монохромную серую палитру, хороший контраст и заметные состояния фокуса.

## Публикация

- Все изменения вносите непосредственно в удалённую ветку `main` через подключённый GitHub; не создавайте отдельные рабочие ветки и PR, если пользователь явно не попросил об этом.
- Для поиска репозитория, чтения его состояния, внесения правок и публикации используйте подключённый GitHub. Не пытайтесь отправлять изменения командой `git push` из локальной копии: в ней может не быть авторизации, а локальные коммиты не являются подтверждением публикации.
- Если текущая рабочая папка пуста или не содержит проект, сначала найдите репозиторий через подключённый GitHub. Не полагайтесь на путь или состояние рабочей копии из прошлой сессии.
- При просьбе «отправить в main» это уже разрешение на прямую публикацию в `main`; не запрашивайте повторное подтверждение.
- После публикации сверяйте через подключённый GitHub содержимое изменённых файлов в `main`.
- Если изменение влияет на GitHub Pages, дополнительно проверяйте опубликованную страницу с обходом кэша и на целевом размере экрана. Не сообщайте, что сайт обновился, пока Pages не отдаёт новую версию; если обновлён только `main`, явно указывайте это различие.

## Технические правила

- Используйте HTML, CSS и нативный JavaScript без сборки и зависимостей, если зависимость не необходима.
- Новую страницу добавляйте в `pages/`, отдельной ссылкой в `index.html` и при необходимости в подходящую группу.
- Для навигации используйте относительные пути, совместимые с GitHub Pages.
- Не отключайте адаптивность, навигацию с клавиатуры и `prefers-reduced-motion`.
- Canvas-анимации должны корректно отображаться на Retina-экранах и не загружать сторонние ресурсы без необходимости.
- Называйте будущие страницы короткими образными названиями на русском, отражающими визуальный характер анимации или эксперимента, а не техническую реализацию. Название должно быть уникальным и использоваться одинаково в каталоге, `<title>` и `data-title`.

## Группа `p5.js`

- Для каждой страницы группы добавляйте запись в раскрытую по умолчанию группу `p5.js` каталога. Порядок, имя файла, название в каталоге, `<title>` и `data-title` должны совпадать.
- Canvas должен быть широким и адаптивным, без фиксированной квадратной ориентации. Размер сцены пересчитывайте при загрузке, изменении размера окна и смене ориентации экрана.
- Ширину canvas ограничивайте доступной шириной контейнера: никаких горизонтальной прокрутки, выхода за края или обрезания на узком экране.
- Соотношение сторон задавайте контейнеру. Canvas растягивайте по обеим осям внутри него; его bitmap не должен определять CSS-высоту в Safari.
- Масштабируйте всю сцену по фактическим границам её объектов с безопасными отступами. При любом соотношении сторон должны быть видны все края анимации, включая верх и низ.
- Проверяйте результат на широком десктопном и узком портретном мобильном экранах, включая поворот устройства. Если анимация рисуется в собственной системе координат, преобразование координат должно сохранять пропорции без искажения.
- После масштабирования координат сцены не используйте этот масштаб напрямую для радиусов точек, толщины линий, теней или иных стилей: ограничивайте их отдельными экранными значениями. На мобильном экране элементы не должны сливаться в сплошную фигуру.
- Перед публикацией проверяйте изменённые HTML-файлы на буквальные последовательности `\\n` вне строк JavaScript и CSS. Они не должны попадать в разметку или Markdown-списки.
- Для каждой новой или изменённой p5-страницы выполняйте визуальную проверку на узком портретном экране: анимация видна целиком, линии и точки различимы, а каталог не содержит постороннего текста.
- Учитывайте `devicePixelRatio`, ограничивая его разумным значением, и `prefers-reduced-motion`; ресурсоёмкие вычисления не должны заметно ухудшать отзывчивость мобильной страницы.
